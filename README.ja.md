# Bluehood Scanner

**[English](README.md) · [日本語](README.ja.md)**

周囲のBluetooth LE電波を受動的に観測し、**別々の場所・別々の日に繰り返し現れる端末**と、
**持ち主から切り離されたトラッカー**を検出するAndroidアプリ。

通信は一切行いません。解析はすべて端末内で完結します。

---

## これは何か

つけられている気がする。でも証拠がない。人間の記憶は反証に弱く、
「同じ人を三回見た」は警察でも扱いに困る主張です。

Bluehoodは、あなたの周囲に実在した電波を淡々と記録し、
偶然では説明しにくいパターンだけを浮かび上がらせます。

- **近隣の可視化** — 周囲の端末が何を漏らしているかを一覧化。名前を名乗る機器は実名で、
  名乗らない機器はベンダーまで。
- **尾行の検知** — **独立した**複数の場所・時間で繰り返し現れた端末だけをスコア化。
  同じ電車に一度乗り合わせただけの人は0点に沈みます。
- **トラッカー検知** — AirTag・Tile・SmartTag等を、持ち主から切り離された状態の
  広告署名から種別判定します。
- **タグの探索** — 自分に付けられたと判定されたタグを、電波強度の相対変化で物理的に探します。
  相手を追う機能ではなく、自分の持ち物を確認するための機能です。
- **オフライン地図** — osmdroidによるOpenStreetMap。Google Play Services不要。
  タイルを事前キャッシュすれば、ネットワーク権限を完全に剥奪しても動作します。

## やらないこと

この種の道具は、簡単に加害の道具になります。以下の境界はドキュメントの約束ではなく
**コードの構造**で担保し、ユニットテストで固定しています。

| | |
|---|---|
| **相手の座標を保存しない** | データベースにその列自体が存在しません。記録されるのは自分のGPSだけです。 |
| **個人を特定しない** | トラッカーは「種別」だけを判定します。スマートフォンの個体識別は行いません。 |
| **能動的な追跡機能を持たない** | 技術的には作れますが、作っていません。単体の端末で得られるのは「自分の近傍の記録」までで、その先が違法な領域だからです。探索タブは例外ではありません。対象は既に自分を追尾していると判定された機器で、得られるのは自分の手元での電波強度だけです。相手の位置は持ちません。 |
| **通信しない** | `INTERNET` 権限を完全に剥奪しても、中核機能はすべて動作します。 |

証拠出力はハッシュチェーンで連結された「自分中心の共起ログ」です。
これは**警察へ提出するための材料**であって、自分で相手を追うためのものではありません。
自力での追跡や対決は、身の安全と法的立場の両方を損ないます。

## 仕組み

BLEのMACアドレスは約15分で回転します。それでも追える理由があります。

**ペイロード指紋。** MACではなく、広告に含まれるサービスUUID・会社ID・送信電力・
ベンダー固有の安定部から指紋を作ります。MACが変わっても指紋は残ります。
どこまでが安定部かはベンダーによって違うので、長さを個別に定めています
（Apple 2バイト、Microsoft 1、Google 0）。

**場所の同定。** 「別の場所か」を、まず周囲のWiFi APの集合で判定します。GPSが無くても
成立するので屋内でも数えられ、屋内測位の揺れで同じ場所が複数地点に割れることもありません
（ルーターは動かず、BSSIDは回転しません）。WiFiが取れないときだけ座標で束ねます（200m）。
WiFiは**スキャンを要求せず**、OSが既に持っているキャッシュを読むだけです。アクティブ
スキャンは自分のMACを載せたプローブ要求を送信してしまい、この道具の目的に反するからです。
BSSIDは端末固有ソルト付きのハッシュにして保存します。生のBSSIDは公開のジオロケーション
DBで座標に復元できるためです。同じ場所で何度見えても加点せず、30分以上空いた再出現だけを
別の機会として数えます。

**厳しい採点。** 最初の2地点は加点しません。生活圏が重なるだけの同僚を尾行と呼ばないためです。
3地点目以降の広がり、時間的な非連続、日またぎが揃って初めて閾値5を超えます。

**至近ゲート。** トラッカーの追尾判定には RSSI ≥ −65 dBm を要求します。鞄やポケットの距離です。
通りすがりの他人のAirTagでは発火しないので、**検知の網を広げても誤検知は増えません**。

**移動が必須。** 追尾とは「自分が動いたのに付いてくる」ことです。200m以上移動していなければ、
「該当なし」ではなく**判定不能**と表示します。
判定できないことによる低スコアが、安全であることによる低スコアと同じに見えてはいけません。

### 実機で見つかった誤検知

ハードウェア上で2種類の誤検知が見つかり、いずれもテストで固定してあります。

- **geohashのセル数は距離の尺度ではない。** セル数で地点を数えていたため、
  103m四方から出ていないのに**3地点**と判定されました。屋内GPSの揺れがセル境界をまたいだためです。
  現在は実距離で数えています。
- **滞在時間は移動の代わりにならない。** 「至近で15分以上」だけで追尾成立としていたため、
  自宅で座っているだけで成立しました。現在は移動を必須にしています。

## 正直な限界

- **PHY指紋はスマートフォンでは不可能です。** 電波の波形そのものから個体を識別するには
  SDR等の専用受信機が要ります。完全に匿名化され広告内容も変化する端末を、
  ローテーションを跨いで確実に再識別することはできません。
- **位置情報サービスが必須です。** `neverForLocation` を宣言していないため、
  位置情報のマスタートグルがオフだとAndroidはBLEスキャン結果を**無言で全破棄**します。
  アプリはこれを検知して明示するので、動いているふりはしません。
- **「おおよその位置」では動きません。** `ACCESS_COARSE_LOCATION` しか持たないアプリには
  Androidがスキャン結果を渡しません。正確な位置を許可してください。
- **ハッシュチェーンは真正性の証明ではありません。** 証明されるのは内部の整合性だけです。
  このアプリを持つ者なら誰でも、任意の内容で整合したチェーンを作れます。
  第三者機関の時刻認証（RFC 3161）が入るまで、「改ざん不可」と説明しないでください。

## インストール

[Releases](../../releases) からAPKをダウンロードしてください。

自己署名のため、インストール時に「提供元不明のアプリ」の警告が出ます。**これは正常です。**
だからこそ各リリースに**APKのハッシュと署名証明書のハッシュ**を併記しています。
現在の値と照合手順は [RELEASE_NOTES.md](RELEASE_NOTES.md) にあります。

APKのハッシュはビルドごとに変わりますが、署名証明書のハッシュは変わってはいけません。

```
797bf4fe07c8b352090b2914491149c6826870429831828d5aca1505c88d8092
```

値が違うリリースは、このプロジェクトの配布物ではありません。
インストールせず、Issueで報告してください。

**Android 13以降**が必要です。GrapheneOS（Pixel 8 Pro）で動作確認しています。

インストール後、以下の3つを有効にしてください。欠けていればアプリがその理由を表示します。

1. Bluetooth
2. 位置情報サービス（システム全体のトグル）
3. 位置情報の権限（**正確な位置**）

## ビルド

```bash
./gradlew assembleDebug          # 開発用
./gradlew testDebugUnitTest      # 検知ロジックのテスト
./gradlew assembleRelease        # keystore.properties が必要（このリポジトリには含まれません）
```

リリースビルドはR8で難読化されます。ProGuardルールで `osmdroid.config` を保護しています
（SharedPreferencesのキーをフィールド名からリフレクションで生成するため、
難読化すると地図が静かに壊れます）。Roomのエンティティも同様です。
